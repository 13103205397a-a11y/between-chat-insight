# 之间 · Between

用 Jev 观察双人聊天里的亲密迹象。它会分别判断主动交流、具体关心、未来计划、明确表达和反向迹象，并给出保留不确定性的结论。数值描述聊天迹象，**不是一个人真实感情的概率**。

## 开始使用

需要 Node.js 20 或更新版本，以及 [TypeSafe / Jev API Key](https://typesafe.ai/)。

```bash
npm install
cp .env.example .env
```

在 `.env` 中填入：

```text
TYPESAFE_API_KEY=你的密钥
```

然后启动：

```bash
npm run dev
```

打开 <http://127.0.0.1:5173/>。可先点击“先用示例对话试试”，再导入自己的记录。修改 `.env` 后请重启服务。

生产构建：

```bash
npm run build
npm start
```

生产页面默认位于 <http://127.0.0.1:8787/>。当前服务只监听本机；若要给其他人在线使用，需要另行部署服务端并配置密钥和访问控制。GitHub 仓库本身不会运行 Jev 接口。

## 导入格式

支持单个或多个 `.txt`、`.md`、`.csv`、`.tsv`、`.json`、`.html`、`.htm`、`.xml` 文件，也支持装有这些文件的 `.zip`。可以读取常见 WhatsApp 文本导出、Telegram JSON/HTML 导出，以及带有“发送者 / 内容 / 时间”字段的通用表格和 JSON。普通文本支持 `2026-08-12 09:15 张三：内容`、`[时间] 张三：内容`、`张三：内容` 等形式。

不同应用和版本的导出结构会变化。导入后请核对消息预览和参与者；无法识别的文件会显示提示。加密的微信数据库、图片截图、语音、视频及附件需要先由原应用导出或转写成可读文本。单个文件上限 20 MB，最多保留 30,000 条文字消息；长聊天会按原始顺序抽取开头、中段和最近最多 180 条供 Jev 判断，页面会显示实际取样数量。

## 隐私与模型

文件由浏览器在本地解析，不上传原文件。点击“开始观察”后，浏览器把选中的双人文字消息发给本机服务；服务抽样并发送到 TypeSafe 的 `POST /v1/systemone` 接口。应用不保存聊天记录、分析结果或 API Key，服务端不会记录聊天正文。请在导入别人的私人聊天前确认你有权处理这些内容，并查看 [TypeSafe 的数据条款](https://typesafe.ai/legal/terms)。

Jev 返回结构化概率，没有自然语言解释。页面不会编造“模型给出的原因”；它只展示各维度判断和明确的阅读边界。其判断未经针对恋爱关系场景的校准，不应作为关系决定的唯一依据。
